## چطور کار می‌کند

```
┌─────────────────┐        HTTPS/JSON        ┌──────────────────────────┐
│   اپ اندروید    │ ───────────────────────▶ │  پلاگین وردپرس (سرور)    │
│  (پل ارسال)     │ ◀─────────────────────── │  mahdinikzad.ir          │
└────────┬────────┘   token in headers       └──────────────────────────┘
         │ SmsManager (سیم‌کارت خودت)
         ▼
     گوشی مقصد
```

- **سرور (پلاگین وردپرس):** لایسنس کاربران، گروه‌ها، مخاطبین، قالب‌ها و صف ارسال.
- **اپ اندروید:** لاگین می‌کند، صف را از سرور می‌گیرد و با `SmsManager` و سیم‌کارت خودِ گوشی می‌فرستد؛ نتیجه‌ی واقعی هر پیام (`SMS_SENT`) را به سرور گزارش می‌دهد.

## ساختار واقعی پروژه

```
app/src/main/java/com/smspanel1/app/
├── MainActivity.kt     رابط کاربری کامل (سه تب: پیام‌ها / مخاطبین / تنظیمات + FAB)
├── SendService.kt      Foreground Service ارسال (مستقل از باز بودن اپ)
└── Net.kt              لایه‌ی شبکه: توکن در هدر + fallback خودکار در صورت حذف هدر توسط هاست

wordpress-plugin/mahdinikzad-sms-gateway/
├── mahdinikzad-sms-gateway.php   API (روت‌ها، دیتابیس، آپدیتر)
└── includes/admin.php            پنل مدیریت وردپرس
```

> توجه: اپ از View برنامه‌نویسی‌شده در Kotlin استفاده می‌کند (بدون Compose/Room/WorkManager). READMEهای قبلی که از Compose و Room حرف می‌زدند با کد هم‌خوان نبودند و اصلاح شدند.

## API (namespace: `smsp1/v1`)

| متد | مسیر | توضیح |
|---|---|---|
| POST | `/login` | ورود و دریافت توکن (بدون احراز) |
| GET | `/diag` | عیب‌یابی کانال توکن — فقط ادمین وردپرس |
| GET/POST | `/groups` | فهرست / ساخت گروه |
| GET/POST/DELETE | `/templates` | قالب‌های پیام |
| GET/POST | `/contacts` | مخاطبین (POST گروهی هم پشتیبانی می‌شود) |
| GET | `/queue` | فهرست کمپین‌ها |
| GET | `/queue/counts` | شمارنده‌ی در انتظار / ارسالی امروز |
| POST | `/build-queue` | ساخت صف از یک گروه + متن پیام |
| POST | `/queue/fetch` | برداشتن پیام‌های در انتظار (اپ) |
| POST | `/queue/update` | ثبت نتیجه‌ی ارسال هر پیام (اپ) |

**احراز هویت:** توکن در هدر `Authorization: Bearer <token>` و همچنین `X-SMSP1-Token`.
اگر هاست اشتراکی هدرها را حذف کند، اپ پس از یک خطای 401 خودکار به حالت `?api_token=` سوییچ می‌کند (نه از ابتدا).

## نصب

### ۱) پلاگین روی وردپرس
1. ZIP پلاگین را از بخش [Releases](../../releases) دانلود کن (`mahdinikzad-sms-gateway-4.3.0.zip`).
2. در وردپرس: **افزونه‌ها → افزودن → بارگذاری افزونه** → نصب → فعال‌سازی.
3. فعال‌سازی، جدول‌های `smsp1_groups`، `smsp1_contacts`، `smsp1_campaigns`، `smsp1_queue` و `smsp1_templates` را می‌سازد.
4. در پنل **پنل پیامکی → لایسنس‌ها** لایسنس کاربر مورد نظر را فعال کن و تاریخ انقضا بده.
5. کاربر در اپ با **نام کاربری/رمز همان کاربر وردپرس** وارد می‌شود.

### ۲) اپ اندروید
- APK را از [Releases](../../releases) بگیر و نصب کن (اندروید ۷ و بالاتر).
- در اولین اجرا این مجوزها را بده: **پیامک** (ارسال)، **مخاطبین** (ایمپورت)، **تلفن** (انتخاب سیم‌کارت)، **نوتیفیکیشن** (وضعیت ارسال در پس‌زمینه).

### ۳) امضای APK (مهم برای آپدیت)
بدون کی‌استور، هر بیلد CI یک امضای متفاوت می‌گیرد و **آپدیت روی نسخه‌ی نصب‌شده نصب نمی‌شود**.

1. `keytool -genkeypair -v -keystore release.keystore -alias smspanel -keyalg RSA -keysize 2048 -validity 10000`
2. در ریپو: **Settings → Secrets and variables → Actions** و این چهار Secret را بساز:

| Secret | مقدار |
|---|---|
| `KEYSTORE_BASE64` | `base64 -w0 release.keystore` |
| `KEYSTORE_PASSWORD` | رمز کی‌استور |
| `KEY_ALIAS` | `smspanel` |
| `KEY_PASSWORD` | رمز کلید |

از آن پس CI با `assembleRelease` بیلد امضاشده می‌سازد؛ بدون این Secretها فقط APK دیباگ ساخته می‌شود.

## ارسال — قدم به قدم

1. تب «مخاطبین» → **➕ گروه جدید** → نام گروه.
2. **📱 از مخاطبین گوشی** یا **📄 از فایل CSV** → مخاطب اضافه کن.
3. تب «تنظیمات» → بازه‌ی فاصله‌ی ارسال (پیش‌فرض ۳ تا ۶ ثانیه، تصادفی) و سیم‌کارت ارسال را انتخاب کن.
4. **➕** → گروه‌ها را تیک بزن → متن را بنویس (یا از قالب انتخاب کن) → **📤 ارسال**.
5. اپ بسته هم بشود، سرویس پس‌زمینه ارسال را ادامه می‌دهد؛ در نوتیفیکیشن دکمه‌ی «توقف» هست.

متن می‌تواند شامل `{نام}` یا `{name}` باشد؛ برای هر مخاطب با نامش جایگزین می‌شود.

## عیب‌یابی

| نشانه | کار |
|---|---|
| «نشست منقضی شد» | ورود از جای دیگر توکن را باطل کرده (هر کاربر یک توکن فعال دارد) — دوباره وارد شو. |
| خطای `401` روی همه‌ی درخواست‌ها | لایسنس غیرفعال/منقضی است یا توکن باطل شده. |
| «در انتظار» پایین نمی‌آید | مطمئن شو اپ روی گوشی مجوز پیامک دارد و یک‌بار اپ را باز کن تا سرویس بالا بیاید. پیام‌های بیش از ۵ دقیقه در وضعیت `sending` خودکار به صف برمی‌گردند. |
| پیامک نمی‌رسد ولی پنل «ارسالی» است | اپ نسخه‌ی قدیمی دارد؛ از v7.1 نتیجه‌ی واقعی `SMS_SENT` ثبت می‌شود. |
| نسخه‌ی نصب‌شده را از کجا بفهمم | تب «تنظیمات» → بالای صفحه «نسخه‌ی اپ: …». |
| لاگ خطا | `adb logcat \| grep -iE "smspanel\|AndroidRuntime\|SmsManager"` |

## تغییرات مهم نسخه‌ها

### v7.2.0 (پلاگین 4.3.0)
- **رفع حلقه‌ی بی‌نهایت درخواست** در تب‌های پیام‌ها و مخاطبین (کاربر بدون کمپین/گروه، سرور را بی‌پایان صدا می‌زد).
- **بارگذاری گروه‌ها در صفحه‌ی ارسال** (قبلاً لیست خالی می‌ماند و ارسال ممکن نبود).
- **دکمه‌ی «➕ گروه جدید» در اپ** — پیش از این ساخت گروه فقط از پنل وردپرس ممکن بود.
- **تأیید واقعی ارسال پیامک** با `SMS_SENT` (پیش‌تر همه‌ی پیام‌ها «ارسالی» ثبت می‌شدند).
- **ارسال به همه‌ی گروه‌های تیک‌خورده** (قبلاً فقط یک گروه).
- **برگشت خودکار پیام‌های گیرافتاده در `sending`** (پلاگین).
- مجوزهای Runtime کامل: `READ_PHONE_STATE` (انتخاب سیم‌کارت) و `POST_NOTIFICATIONS`.
- سرویس در نبود مجوز پیامک یا خطای 401/403 خودش را متوقف می‌کند (بدون تلاش بی‌پایان).
- **قالب‌های پیام** واقعی شدند: جدول + روت‌های `/templates` + دکمه‌ی «ذخیره‌ی این متن به‌عنوان قالب» در اپ.
- امنیت: توکن دیگر همیشه در URL نمی‌رود؛ `/diag` فقط برای ادمین؛ توازن مسیر سرور.
- UX: FAB شناور روی محتوا (نه زیر تب‌بار)، نوار خلاصه‌ی آمار جدا، نشان‌دادن نسخه‌ی اپ، دکمه‌ی جستجو واقعاً به تب مخاطبین می‌رود، پیش‌نویس متن حفظ می‌شود.
- ورک‌فلو: یک ورک‌فلو/یک ریلیز در هر پوش، بیلد امضاشده، نام‌گذاری asset پلاگین با نسخه برای آپدیتر درست.

### v7.0.2 و قبل‌تر
تاریخچه‌ی قبلی: رابط ساده‌ی سه‌تبی، سرویس Foreground، تاریخ شمسی، ایزوله‌سازی چندکاربره.

## محدودیت‌های شناخته‌شده

- **یک توکن فعال برای هر کاربر:** ورود از گوشی دوم، توکن گوشی اول را باطل می‌کند.
- گزارش تحویل (`SMS_DELIVERED`) ثبت نمی‌شود؛ فقط نتیجه‌ی «تحویل به مرکز پیام» (که دقتش از قبل بسیار بیشتر است).
- سرویس پس از ۱۰ دقیقه بی‌کاری خودش را می‌بندد و با باز شدن اپ یا ساخت صف جدید دوباره بالا می‌آید.

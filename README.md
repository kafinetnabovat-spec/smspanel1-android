# SmsPanel1 — پنل پیامکی اندروید

کلاینت فارسی وردپرس برای مشاهده مخاطبان و صف پیامک و ارسال از **سیم‌کارت دستگاه**. Android 7.0 (API 24) به بالا؛ ارسال نیازمند رضایت مخاطب، مجوز `SEND_SMS` و سیم‌کارت فعال است. هزینه هر بخش پیام را اپراتور محاسبه می‌کند.

## قابلیت‌های موجود

- رابط Compose / Material 3 با دو تب پیام‌ها و مخاطبان، جستجو و فیلتر گروه/وضعیت.
- ورود به نشانی HTTPS وردپرس، انتخاب چند گروه و استفاده از متن قالب در ایجاد صف.
- فقط یک مصرف‌کننده صف در `SmsForegroundService`؛ شروع و توقف **صریح توسط کاربر** از نوار بالای برنامه و توقف از اعلان.
- درخواست مجوز پیامک هنگام شروع ارسال؛ رد مجوز باعث مصرف صف نمی‌شود.
- ثبت `sent` فقط بعد از callback موفق **تمام بخش‌های پیامک**. این وضعیت به معنی تحویل به گیرنده نیست؛ delivery receipt پیاده‌سازی نشده است.
- دفتر ثبت محلی وضعیت ارسال، تفکیک‌شده بر اساس سایت و شناسه کاربر؛ خطای به‌روزرسانی سرور فقط همان به‌روزرسانی را تکرار می‌کند، نه ارسال پیامک را.
- توکن در `Authorization: Bearer`، ذخیره‌سازی رمز‌شده، جلوگیری از HTTP و redirect، بدون fallback به ذخیره‌سازی ساده یا ثبت شماره/متن/توکن در لاگ.
- خروج و 401 نشست را پاک و ارسال را متوقف می‌کنند. داده‌های نمایشی و درخواست‌ها به نشست کاربر محدود هستند.
- نمایش شمسی، محاسبه امروز/دیروز با روز تقویمی (نه تقسیم میلی‌ثانیه)، پشتیبانی از offset در زمان ISO و اعتبارسنجی تاریخ. محدوده تبدیل این نسخه: ۱۹۰۰ تا ۲۱۰۰ میلادی؛ تاریخ خارج از محدوده به شکل ورودی نشان داده می‌شود.

## روش استفاده

1. افزونه سازگار با قرارداد API زیر را روی سایت HTTPS نصب کنید. **کد افزونه داخل این مخزن نیست.**
2. گروه‌ها، مخاطبان و قالب‌ها را در پنل وردپرس مدیریت کنید؛ واردکردن فایل مخاطبان در برنامه پیاده‌سازی نشده است.
3. در برنامه وارد شوید، از دکمه `+` گروه‌ها و متن را انتخاب و ایجاد صف را تأیید کنید.
4. `شروع ارسال` را بزنید و مجوز پیامک را بدهید. این دکمه کل صف معلق همین حساب را پردازش می‌کند، نه فقط آخرین صف ایجادشده.
5. برای دیدن آخرین وضعیت از بروزرسانی استفاده کنید. ارسال با `توقف ارسال`، توقف اعلان یا خروج قطع می‌شود. پیام تحویل‌داده‌شده به مودم قابل پس‌گرفتن نیست.

در گوشی دوسیم‌کارته، سیم‌کارت پیش‌فرض پیامک را در تنظیمات اندروید تعیین کنید. انتخاب سیم‌کارت داخل برنامه هنوز وجود ندارد.

## ایمنی ارسال و محدودیت‌ها

- قبل از فراخوانی مودم، وضعیت `sending` به‌صورت پایدار ثبت می‌شود. وقفه، کشته‌شدن فرایند یا نرسیدن callback ممکن است نتیجه را نامشخص کند؛ برنامه برای جلوگیری از پیامک تکراری **همان شناسه را خودکار دوباره ارسال نمی‌کند**. این انتخاب ممکن است یک پیام ارسال‌نشده را نیز برای بررسی نگه دارد.
- در پیام چندبخشی، `failed` می‌تواند به معنی شکست بعضی بخش‌ها باشد؛ ارسال مجدد کل پیام بدون بررسی ممکن است بخش‌های تکراری بسازد.
- رکوردهای دفتر ارسال پس از خروج باقی می‌مانند، اما فاقد شماره، متن و توکن هستند. حذف داده‌های برنامه/نصب مجدد این محافظت را از بین می‌برد. برای پیام نامشخص، ابتدا پنل، اپراتور و گیرنده را بررسی کنید؛ فقط در صورت نیاز، صف جدید با شناسه جدید بسازید.
- بعد از reboot، force-stop یا توقف فرایند، شروع مجدد **دستی** لازم است. WorkManager، دریافت boot، ادامه تضمینی و ارسال دقیقاً یک‌بار در چند دستگاه پیاده‌سازی نشده‌اند.
- محدودیت باتری، سهمیه سرویس پس‌زمینه و محدودیت تعداد SMS اپراتور/اندروید برقرار است؛ بسته‌شدن رابط کاربری با force-stop یکسان نیست.
- ساخت صف چندگروهی چند درخواست جداگانه است. قطع شبکه ممکن است صف را فقط برای بعضی گروه‌ها ایجاد کرده باشد؛ **قبل از تلاش دوباره صف را بررسی کنید**. حذف مخاطب تکراری بین گروه‌ها و idempotency ساخت صف باید در سرور انجام شود.
- حفاظت محلی جای کنترل دسترسی سرور را نمی‌گیرد. جلوگیری از IDOR، مالکیت گروه/مخاطب/صف، انقضای توکن، محدودسازی نرخ و برداشت اتمیک صف مسئولیت افزونه وردپرس است.
- این نسخه Room/کش آفلاین، واردکردن CSV، رسید تحویل و دکمه ارسال مجدد ناموفق‌ها ندارد. وابستگی‌های استفاده‌نشده حذف شده‌اند.

## قرارداد مورد انتظار سرور

همه مسیرها نسبت به `<site>/wp-json/smsp1/v1/` هستند. نشانی نصب در زیرپوشه نیز پذیرفته می‌شود. redirect پذیرفته نمی‌شود؛ آدرس نهایی HTTPS را وارد کنید.

| روش / مسیر | درخواست / پاسخ |
| --- | --- |
| `POST login` | `{username,password}` → `{user_id,api_token}`؛ `api_key` یا پاسخ داخل `data` نیز پذیرفته می‌شود |
| `GET groups` | آرایه `{id,name,descr?,contact_count?}` |
| `GET contacts` | آرایه `{id,name,mobile,group_id?}` |
| `GET templates` | آرایه `{id,title,body}`؛ فقط 404 به معنی نبود قابلیت است |
| `GET queue` | آرایه `{id,receiver,body,status,created_at}` |
| `GET queue/counts` | `{pending,sending,sent,failed}`؛ در 404 شمارش از صف خوانده‌شده محاسبه می‌شود |
| `POST build-queue` | `{group_id,template_id,manual_body,product_ids:[]}` → `{queued,campaign_id}` |
| `POST queue/fetch` | `{limit:1}` → آرایه `{id,receiver,body}`؛ برداشت/رزرو باید اتمیک و مختص کاربر باشد |
| `POST queue/update` | `{id,status}`؛ مقادیر `sending`، `sent`، `failed` و تکرار امن همین وضعیت باید پشتیبانی شوند |

شناسه‌های صف باید برای هر حساب یکتا و غیرقابل استفاده مجدد باشند. سرور باید بازگرداندن صف رزروشده را مدیریت کند. شمارش و لیست‌های صفحه‌بندی‌شده بدون قرارداد pagination در این نسخه پشتیبانی نمی‌شوند. زمان بدون offset در منطقه زمانی دستگاه تفسیر می‌شود؛ برای سایت با منطقه زمانی متفاوت، سرور باید ISO 8601 با offset بدهد. قالب در رابط فعلی به‌عنوان متن اولیه کپی می‌شود؛ توسعه متغیرهای قالب مسئولیت سرور است.

## ساخت و تست

پیش‌نیازها: **JDK 17**، Android SDK Platform 34 و Build Tools 34.0.0، دسترسی به Google Maven / Maven Central و Gradle. مسیر SDK را در `ANDROID_HOME` یا `local.properties` (خارج از Git) تنظیم کنید.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug --no-daemon
```

خروجی: `app/build/outputs/apk/debug/app-debug.apk` — نسخه debug برای آزمایش، نه بسته امضاشده انتشار.

GitHub Actions همین دستور را برای push روی شاخه‌های تنظیم‌شده، pull request و اجرای دستی اجرا می‌کند و APK و گزارش‌ها را در **Artifacts** می‌گذارد. انتشار عمومی Release به‌صورت خودکار انجام نمی‌شود.

تست‌های JVM: اعتبارسنجی URL، نوروز و مرز ماه/سال، سال کبیسه، DST/offset، ورودی خراب و تجمیع callbackهای چندبخشی. چک‌لیست آزمون واقعی و وضعیت اعتبارسنجی این تغییرات در [docs/VALIDATION.md](docs/VALIDATION.md) است.

## انتشار و رضایت

فقط به گیرندگان دارای رضایت و با روش لغو عضویت پیام ارسال کنید. مجوز `SEND_SMS` مشمول سیاست‌های محدودکننده فروشگاه‌ها است. هدف SDK این مخزن 34 است؛ پیش از انتشار در فروشگاه، الزامات روز target SDK، نوع Foreground Service و مجوزها باید دوباره بررسی شوند. این مخزن فایل LICENSE ندارد؛ ادعای مجوز MIT نسخه قبلی حذف شده و مجوز انتشار باید توسط مالک مشخص شود.
